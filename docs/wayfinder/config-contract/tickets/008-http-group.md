## Question

Nothing to decide — build the approved contract for real, carrying exactly one
group through every consumer. This is the tracer bullet: the pattern the
remaining group slices copy.

Done when:

- the contract module exists, tested, with the HTTP / sync group declared in it
- the public nested shape for that group ships, and the flat fields it replaces
  are gone
- both native mappers handle the group, kept honest by whichever mechanism was
  chosen
- the docs table rows for those fields derive from the contract — the shipped
  drift in this group's defaults disappears rather than being hand-corrected
- the example app's rows for those fields read defaults, ranges and platform
  ownership from the contract instead of restating them
- the published defaults are reachable by callers, since reset is now expressed by
  passing a default explicitly
- `url` and `syncUrl` default to `""` on **both** platforms — a behaviour change on
  iOS, where they currently default to nil
- `null` appears in the type of `httpHeaders` and `postTemplate` only, as a value
  meaning "set this to nothing"; passing it anywhere else in this group is a
  compile error
- a write to a foreign-owned field is dropped as before but emits a dev-mode
  warning naming the field and its owning platform
- `getConfig()` no longer crashes on a fresh install when no post template has
  been stored — the unconditional read is of `postTemplate`, an HTTP-group field,
  so it is fixed where this group's read path is rewritten
- `CONFIG_FIELDS` ships with this group's entries, as a plain-TypeScript export
  outside the nitro spec, and `AppliedConfig` returns the group fully populated
- configuring a URL and reading it back works on both platforms, and a read
  reports foreign-owned fields the way the read decision says it should

Record in the resolution how many edits adding a field to this group now takes,
measured rather than estimated.

## Resolution

**The tracer bullet is through.** The Config Contract exists, the HTTP group runs
end to end on both platforms, and adding a field to it now costs **one contract
edit plus one native storage slot per platform — measured, not estimated**.

### What was built

| Artifact | Authored or generated |
| --- | --- |
| `HTTP_CONTRACT` in `src/NitroBackgroundGeolocation.nitro.ts` | **authored** — the only place an HTTP configuration fact is written |
| `HttpOptions` / `HttpConfig` / `AppliedConfig` | generated by nitrogen from mapped types over the contract |
| `src/contract.ts` — `CONFIG_FIELDS`, `HTTP_DEFAULTS`, `ownsField()` | derived at runtime, plain TypeScript, outside the nitro spec so no JSI crossing |
| `generated/HttpDefaults.kt`, `generated/HttpMapper.kt` | generated by `yarn generate:config` |
| `ios/generated/HttpDefaults.swift`, `ios/generated/HttpMapper.swift` | generated |
| `apps/docs/docs/generated/_config-http.md` | generated, committed, imported by the configuration page |
| `HttpConverters.kt` / `HttpConverters.swift` | **authored** — the declared converter escapes |

`ConfigureOptions.url`, `.syncUrl`, `.syncThreshold`, `.httpHeaders` and
`.postTemplate` are gone; the group is reachable only as `http`. `getConfig()`
returns `AppliedConfig`, whose `http` is complete.

### Measured cost of adding a field

A throwaway `requestTimeout` entry was added to the contract, then reverted. One
edit produced **64 changed files** across the two generators, and the Kotlin
compiler then demanded exactly three things — all the same missing native storage
slot:

```
HttpMapper.kt:15:43 Unresolved reference 'setRequestTimeout'.
HttpMapper.kt:25:38 Unresolved reference 'requestTimeout'.
```

So: **1 contract edit + 1 storage slot per platform**, with the compiler naming
the slot for you. Before this map it was five hand edits plus nitrogen plus
native plus docs, with drift possible at every step. Drift is now structurally
impossible for this group: the docs row, both mappers, the native defaults and
the public type all come from the same entry.

### Native defaults stopped being authored

`Config.getDefault()` now reads `HttpDefaults.url`, `.syncUrl`, `.syncThreshold`,
`.httpHeaders` and `.postTemplate` instead of holding literals. This is the
generated-code-inside-the-vendored-package cost that
[the mechanism decision](004-contract-mechanism.md) accepted, and it is real: a
reader of `Config.java` no longer sees the values there.

### The Objective-C core also stopped holding a default

`MAURConfig.initWithDefaults` still had `syncThreshold = 100` — a second authored
copy that the reads shadowed but did not remove. Swift constants are invisible to
Objective-C, so the generator now also emits `ios/generated/HttpDefaults.h` with
`#define`s, and `MAURConfig.m` includes it. `url` and `syncUrl` deliberately stay
`nil` in that initialiser: their getters already coerce nil to `""`, so the
contract default holds without changing what `hasValidUrl` reports and therefore
without changing posting behaviour.

### Bug fixed on the way

`getConfig()` crashed on a fresh install because `MAURConfig.toDictionary` was
the one line without a nil guard — `[dict setObject:self._template ...]` raises
when `_template` is nil, which it is until a template is set. Now guarded by
`hasTemplate`, matching every other line in that method.

### Both platforms build

- **Android** — `BUILD SUCCESSFUL`, Kotlin plus the JNI C++ via
  `buildCMakeDebug[arm64-v8a]`, verified by symbols in the built `.so` rather
  than by the app build (which goes green without recompiling the library's C++).
- **iOS** — `** BUILD SUCCEEDED **` for the pod target, verified against build
  products: `HttpMapper.o`, `HttpDefaults.o` and `HttpConverters.o` exist for
  both `arm64` and `x86_64`. `pod install` needs a UTF-8 locale override, as the
  build check recorded.

### A finding worth carrying into 009 / 010

**The same field's null variant gets two different generated type names**
depending on optionality: the write side derives an inline
`Variant_NullType_Map_String__String_`, while the read side keeps the declared
alias `NullableHeaders`. Both platforms hit it as a compile error. The fix that
scales: generated mappers never name a variant type — they call a converter
escape, and the hand-written escape carries the platform-specific signature. That
also keeps the null-as-value branching (which cannot use `?.let`) out of
generated code.

### Tests

39 tests in the library package, 92 across the monorepo, all passing with
`yarn turbo run test`. Beyond the headless suite, `contract.test.ts` guards the
invariants the prototype discovered the hard way: every field declares platforms,
native keys and prose; a null-defaulting field declares its native type on both
platforms; no name is a reserved word; the contract is **not** frozen with
`as const`; the published defaults match the contract; `CONFIG_FIELDS` is keyed
by dotted path and carries the range metadata; both null-permitting fields route
through a converter escape rather than `?.let`; `Config.java` no longer holds an
authored default; the docs row escapes the pipe in a union type; the Objective-C header carries the
threshold and `MAURConfig` no longer holds it; and the `postTemplate` read is
guarded.

The generator also refuses to emit rather than emitting broken native code: it
throws when a field is a reserved word, declares no platforms, has no
description, is owned by a platform without a native key, or defaults to null
without a declared native type.

### Consumers migrated

- The docs configuration page imports the generated partial as its "HTTP and
  sync" section, and every flat HTTP example across `configuration.md`,
  `http-posting.md` and `getting-started.md` is nested under `http`.
- The example settings screen writes through a group-aware `updateHttp` and reads
  defaults from `HTTP_DEFAULTS` — including the subtitle that used to hardcode
  "Default 100", which now interpolates.
- The session detail screen addresses fields by dotted path (`http.url`), so its
  rows survived the shape change with a path resolver rather than a rewrite.

### Repo hygiene fixed while here

`vitest.config.ts` and `scripts/` were being compiled into `lib/typescript/`, and
the package tsconfig lacked a `lib` exclude, which made `typecheck` fail on stale
output. Both fixed; `@types/node` added for the generator script.
